# Project Report Collaboration Insights

El repositorio público del informe se encuentra organizado bajo la organización de GitHub del equipo, siguiendo la
convención de nomenclatura establecida en el enunciado del trabajo final. El informe está redactado en formato
Markdown, con estructura de carpetas por capítulo.

Repositorio del informe:
https://github.com/UPC-RebooTech/FruitLogix-report.git

El repositorio aplica GitFlow como workflow de control de versiones y Conventional Commits para los mensajes de
commit, y Semantic Versioning para cada versión de release.

# AV1: Sprint Review

Durante la elaboración de la entrega AV1, el equipo se organizó trabajando colaborativamente en los dos capítulos
principales del informe, que son el capítulo 1 y el capítulo 2. Se realizaron reuniones de trabajo por Google Meet y
por cada capítulo se creó una rama para trabajar de manera independiente, con el objetivo de que cada integrante del equipo pueda aportar en paralelo a la redacción del informe.
Una vez que se finalizaba un capítulo, se procedía a aplicar los cambios a las ramas develop y main, con el apoyo de la herramienta GitFlow Helper.

# TB1: Sprint Review

Durante el desarrollo de los entregables correspondientes al TB1, el equipo se organizó trabajando colaborativamente en los dos capítulos
asignados para este envío, que son el capítulo 3 y el capítulo 4, así como de la implementación inicial de la Landing Page, Backend y Mobile App.
Nuevamente, se realizaron reuniones de trabajo por Google Meet. El flujo de trabajo para el informe permaneció igual, y para la Mobile App
también se aplicaron ramas, aunque esta vez por cada funcionalidad, de manera que los integrantes puedan trabajar en diferentes Bounded Context sin conflictos a la hora de unir los cambios.
Cuando se finalizaba un feature, al igual que con el informe, se procedía a aplicar los cambios a las ramas develop y main, con el apoyo de la herramienta GitFlow Helper.
