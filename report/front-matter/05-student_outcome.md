| Actualiza conceptos y conocimientos necesarios para su desarrollo profesional y en especial para su proyecto en soluciones de software. | **AV1**:<br/>Renzo: Para este primer avance del proyecto, reforcé las estrategias aprendidas en cursos anteriores para tener un mejor control de los proyectos: GitFlow, Conventional Commits, Semantic Versioning, manejo de Jira, entre otros. Asimismo, al tomar el rol de líder del nuevo grupo de trabajo y reutilizando un trabajo ya existente, tuve que aplicar lo aprendido previamente para coordinar a los integrantes del equipo y saber orientarlos para elaborar el proyecto lo mejor posible. Destaco como fortaleza el organizar bien a mi grupo de trabajo, en saber asignarles las actividades y de siempre estar dispuesto a atender sus dudas; lo cual me permitió manejar mejor el proyecto y a acostumbrarme a otras posibles soluciones de esta magnitud.<br/>Esteban: Aplicó nuevas herramientas de diagramación colaborativa para la elaboración del Big Picture Event Storming del proyecto FruitLogix, apoyándose en documentación oficial y bibliografía especializada en Domain-Driven Design para aplicar correctamente la notación del método. Empleó técnicas de investigación cualitativa, diseño de guías de entrevistas y needfinding, para indagar el problema real de los distribuidores de fruta con los stakeholders del dominio. Asimismo, consultó bibliografía y documentación oficial de la metodología Lean UX para estructurar el Capítulo I del informe (Startup Profile, Solution Profile, Problem Statements, Assumptions, Hypothesis Statements y Lean UX Canvas), aplicando por primera vez estos conceptos metodológicos al proyecto.<br/>Sebastian: Durante la definición arquitectónica de FruitLogix, apliqué conceptos técnicos avanzados sobre Domain-Driven Design. Al asumir el diseño táctico de los Bounded Contexts de Payment Management e Infrastructure & IoT, investigué cómo desacoplar bases de datos, definir raíces de agregados (Aggregate Roots) o establecer contratos claros entre diferentes servicios. Además, la estructuración de las Spike Stories me exigió estudiar protocolos de telemetría, persistencia offline o integración de pasarelas nativas como Stripe. Abordar este nivel de exigencia requirió analizar documentación oficial extensa, comparar alternativas tecnológicas para luego plasmarlas coherentemente utilizando el modelo C4. Toda esta experiencia evidenció mi capacidad para adquirir nuevos conocimientos orientados a resolver problemas complejos de ingeniería.<br/>Durante el desarrollo de FruitLogix amplié y apliqué conocimientos que no manejaba completamente al inicio, principalmente sobre Domain-Driven Design, EventStorming, Domain Storytelling, Context Mapping, modelo C4 y el uso de Structurizr para representar la arquitectura de software. Para desarrollar estas secciones tuve que revisar el statement del proyecto, contrastar requisitos, analizar el trabajo previo de FruitLogix y validar que las decisiones tomadas fueran coherentes con el dominio logístico y agroindustrial, además de considerar aspectos de IoT, pagos y desarrollo móvil. Considero que una fortaleza de estas herramientas es que permiten organizar mejor las responsabilidades del sistema y mantener trazabilidad entre requisitos, dominio y arquitectura; sin embargo, también requieren bastante análisis y evidencia para evitar definir límites o relaciones incorrectas. Este proceso me permitió mejorar mi capacidad para investigar, comparar fuentes, cuestionar decisiones anteriores y aplicar nuevos conceptos de manera justificada dentro de una solución real de ingeniería de software.<br/>Camila: Durante la entrega, reforcé y apliqué conceptos de Domain-Driven Design (DDD) y Clean Architecture para estructurar correctamente el proyecto. Diseñé dos Bounded Contexts completos (Profiles Management y Logistics and Monitoring), organizando sus capas con Aggregate Roots, Value Objects, el patrón CQRS y su persistencia con EF Core. Para respaldar este diseño, elaboré los diagramas de componentes en Structurizr DSL, diagramas de clases de dominio y el modelo físico en PlantUML. Además, estructuré el Product Backlog completo en Jira, estimando y distribuyendo 81 user stories y tareas técnicas en 4 Sprints para asegurar un desarrollo ágil y ordenado. | |
